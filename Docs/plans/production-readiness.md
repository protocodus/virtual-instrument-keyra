# Keyra production target

The target is an expressive, dependable acoustic-piano instrument priced above
USD 199. The price is a commercial decision. Isolated-note error reductions
alone cannot establish that customers will value it at that price.

## Required behavior

- Full A0–C8 keyboard, continuous velocity response, repeated notes and overlapping
  release tails, with stable deterministic rendering across audio block sizes.
- Continuous sustain (CC64), half-pedal damping and repedaling; sostenuto (CC66)
  captures keys held at its rising edge; soft pedal (CC67) changes excitation.
- Mod wheel (CC1) smoothly damps sounding strings, including held keys. It acts
  on the model's decay rather than abruptly gating the output.
- Common MIDI reset and panic commands; channel ownership; pitch bend and
  tuning; robust state recall and automation in the DAW and Rack wrappers.
- Visible soft/sostenuto/sustain pedals with effective travel feedback and
  below-piano momentary keyswitches 12/13/14, independent of MIDI CC and saved
  panel travel. No piano tone is generated by those switches.
- One front-end-neutral engine, with DAW and Reason adapters consuming the same
  source. No copied or separately patched Rack model.
- Polished, readable wood and ivory interface with clear control ownership and
  real bound controls on every supported panel.

## Evidence required before a commercial release

| Gate | Required evidence |
| --- | --- |
| Tone and dynamics | Reproducible train-only calibration; all held-out and edge cases reported, including regressions; independent recording set from another piano/microphone setup |
| Playing realism | Recordings with documented MIDI and pedal timing for half-pedal, repedaling, sostenuto, soft pedal, repeated notes and chords; comparisons through the exact product engine |
| Listening | Level-matched full musical passages, multiple experienced pianists, and explicit owner decisions for audible alternatives measurements do not settle |
| Reliability | Allocation-free callbacks, sample-accurate controllers, rate/block coverage, long tails, silence, panic and malformed-input/state handling; sanitizers |
| DAW hosts | Exact built candidate loaded, played, saved, reopened and automated in representative Windows/macOS DAWs; parameter/state migration and offline bounce checks |
| Performance | Development-machine CPU measurements plus actual DAW/Reason measurements at 44.1/48/96 kHz and supported block sizes, including heavy pedal polyphony |
| Rack | Licensed SDK build, `.u45` archive check, exact-candidate creation/view checks and full Reason acceptance in an isolated test host |
| Delivery | Versioned binaries, matching screenshots and guides, notices, checksums, installers/signing as applicable and verified publication status |

The preserved nonlinear reference and the real-time reduced model are separate
implementations with different approximations. Do not transfer the reference's
physics-validation results or musical examples to the live candidate as if they
were candidate measurements. The current recording library has undocumented
pedal acquisition state, so it cannot validate pedal fidelity.

## Iteration discipline

Keep the calibration split `Tools/corpus/split-2026-10-27.json` locked: fit
only its train role, score its dev role at every iteration without fitting
it, and open the sealed pitches (D♯2, D♯4, D♯6) only to report a candidate the
owner is asked to approve, logging each opening in
`Tools/corpus/sealed-openings.json`. Dev results choose between candidates, so
they are development evidence; only a sealed opening is a first look. The
preserved research split's ten training, twelve held-out and two extreme cases
remain as labels in `Tools/evaluate_recordings.py`, so reports stay comparable
with earlier ones.

Prefer improvements to measured attack, partial balance and decay which survive
held-out cases. Report tradeoffs and per-case regressions, rather than one
aggregate percentage. Treat a functional development candidate as progress
toward the commercial target; call it production ready only after the gates
above have evidence.
