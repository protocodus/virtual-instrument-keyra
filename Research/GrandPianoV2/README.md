# Grand piano physical-model POC — v2

This is the preserved offline research baseline imported into Keyra on 2026-10-26. The solver and calibration header are byte-identical to the completed v2 study. The checked-in MP3s and measurement reports describe that reference, not a future optimized engine. See [import provenance](import-provenance.json).

A standalone, sample-free, 88-key piano model calibrated against recordings of an acoustic grand. The sound is generated by nonlinear hammer contact, dispersive strings and a reciprocal string/bridge/soundboard simulation. Numeric parameters derived from recordings are compiled into the model; it loads no recorded waveform, sample bank or impulse response.

The delivery includes four original musical excerpts, a diagnostic study, six real/v1/v2 listening comparisons and all 24 measured reference comparisons. The bundled [frozen v1 source](benchmark/baseline_source/grand.cpp) preserves the baseline.

## What changed

The model now uses measured tuning, inharmonicity and frequency-dependent losses from a fixed training set. Passive common-unison damping separates a faster collective decay from the slower relative motion of detuned strings. A revised velocity curve reduces the excessive soft-to-hard contrast of v1.

The output observation uses a fitted modal radiation magnitude for each string polarization. This retains the phase of the analytic loaded soundboard transfer and its time-domain transient. It is an empirical observation model, not a recovered finite-element soundboard or a unique identification of the instrument's physical parameters. The coupled mechanical simulation remains active. See [MODEL.md](MODEL.md) for equations and limitations.

## Benchmark against real recordings

The reference is **Salamander Grand Piano V3 by Alexander Holm**, a Yamaha C5 recording set distributed under [CC BY 3.0](https://creativecommons.org/licenses/by/3.0/). The 24 selected files, source commit and hashes are documented in [reference/ATTRIBUTION.md](reference/ATTRIBUTION.md) and [reference/manifest.json](reference/manifest.json). These recordings are used for calibration and comparison, not as synthesis assets.

The [split](benchmark/split.json) was fixed before fitting:

| Set | Cases | Purpose |
|---|---:|---|
| C2–C6, velocity layers 4 and 12 | 10 | Parameter fitting |
| Velocity layers 6 and 8 excluded from fitting | 8 | Velocity generalization |
| F♯2–F♯5, layer 8 | 4 | Pitch interpolation |
| C1 and C7, layer 8 | 2 | Separate extrapolation check |

Only the ten training cases enter calibration. SFZ velocity-bin midpoints are model inputs; they are not measured hammer speeds or confirmed MIDI velocities of the recorded strikes. Acquisition pedal state is undocumented, so these files do not validate pedal realism.

[BENCHMARK.md](BENCHMARK.md) explains alignment, one-gain level matching, spectral and decay measurements, the frozen v1 baseline and all completed results. Across 12 notes excluded from fitting within C2–C6, harmonic-level error falls from 11.03 to 4.96 dB and decay-slope error from 3.88 to 2.83 dB/s. Attack-rise error increases from 8.29 to 19.17 ms; pitch-interpolation envelopes and several upper-register/edge cases also regress. Error reductions measure agreement with this recording set; they are not percentages of realism. A [shared-scale C4 spectrogram and envelope plot](benchmark/report/C4v8-spectrogram.png) shows both improved early decay and residual late-tail mismatch.

Each 13.25-second triplet uses onset-aligned 4.05-second excerpts and 0.55-second gaps. One early-RMS gain per model remains fixed through the decay; a common final gain gives the set a maximum estimated true peak of −2 dBTP. No room, compression or limiter is added. The real excerpts are Alexander Holm's CC BY 3.0 recordings, aligned, end-faded and concatenated for comparison; see [attribution](reference/ATTRIBUTION.md) and the [listening manifest](listening/manifest.json). These are labeled listening aids, not a blind test.

All five supplied performances were synthesized at 192 kHz, FIR-downsampled to 48 kHz and exported as stereo 24-bit PCM with TPDF dither. MP3 previews are 320 kb/s. Room versions add procedural reflections and a diffuse tail; no recorded room response is used. Dry files are the most direct way to judge the synthesis. A shared −10.07 dB export gain preserves dynamics across all ten dry/room WAVs, without compression or limiting; the maximum estimated true peak is −1.50 dBTP. [Export metrics](renders/metrics/export.json) include durations, levels, output hashes and verified native-render provenance for the frozen source and calibration.

## Reproduce

Requires a C++17 compiler and Python 3.10+ with NumPy/SciPy. `ffmpeg` provides MP3 previews and reference FLAC decoding. The synthesis engine uses only the C++ standard library. Run from this directory:

```sh
python3 -m pip install -r requirements.txt
python3 tools/make_scores.py
python3 tools/render.py --jobs 4
python3 tools/validate.py --audio
```

The renderer builds the engine and runs its self-test before export. This is an offline quality renderer, not a real-time performance claim. Use `--internal-rate 96000` for cheaper previews; supplied musical masters target 192 kHz. Recorded `realtime_factor` means wall seconds per audio second.

To render another performance:

```sh
python3 tools/render.py --midi performance.mid --name my_performance
python3 tools/render.py --events performance.events --name my_performance
```

The MIDI importer supports format 0/1 tempo maps, note events and continuous CC64 sustain; percussion channel 10 is excluded by default. Timed events use seconds, MIDI note numbers and velocity:

```text
0.000000 pedal 0 1.0
0.100000 on 60 85
1.000000 off 60 0
2.000000 pedal 0 0.0
```

Native float32 output is a pressure proxy with arbitrary gain and may exceed ±1. Use the Python export pipeline for listening files. Native `--bridge`, `--hammer-loss`, `--loss`, `--damper` and `--uncalibrated` are research controls. `--no-sympathetic` disconnects ports of keys never struck; its output observation is not separately recalibrated. The preserved v1 executable, rather than `--uncalibrated`, is the benchmark baseline.

This checkout includes the exact solver and numeric calibration, tools, scores, 11 MP3 previews, benchmark features/reports, figures, numerical evidence and reference attribution. Original FLACs, decoded reference WAVs, 24-bit demo/comparison WAVs, compiled binaries and native scratch renders are not tracked. The MP3 previews remain immediately playable.

Run `python3 reference/fetch_reference.py` to restore the pinned licensed FLAC files and decode the reference WAVs. `python3 tools/render.py --jobs 4` regenerates all dry/room PCM24 musical masters and MP3 previews. The [benchmark reproduction commands](BENCHMARK.md#reproduce-the-evidence) regenerate native isolated-note WAVs; after regenerating both `benchmark/baseline/` and `benchmark/candidate/`, `python3 tools/make_listening.py` recreates the comparison WAVs and MP3s. The imported JSON evidence retains historical file hashes and machine paths as provenance. These are records of the completed v2 experiment, not runtime dependencies. Re-running extraction/rendering records new paths and potentially new container/compiler hashes. The imported solver and calibration SHA-256 values remain the authoritative source identity.

## Limits

There is no blind listening panel or claim of Pianoteq parity. Training spans one instrument, one microphone arrangement and five anchor pitches. Geometry, hammer felt, bridge mobility, dampers and room response still contain authored approximations. Missing mechanisms include longitudinal/phantom partials, geometric string nonlinearity, hereditary felt memory, duplex strings, action noise and detailed lid/rim radiation. Sustain and sympathetic transfer work numerically, but their strength is not calibrated against pedal-controlled recordings.

The POC source and original musical performances were created locally for this task. The reference recordings retain Alexander Holm's CC BY attribution. Research papers linked from [MODEL.md](MODEL.md) remain under their respective licenses; their source code and neural weights are not bundled.
